Quickstart

  1. Get an API key

    Create an account at api.soroswap.finance/register, log in at /login and generate a key. It starts with sk_ and goes in every request as Authorization: Bearer sk_.... Stuck? Find the Soroswap team at the venue or ping us on Discord.

  2. Get a wallet and some funds

    Install Freighter and switch it to Testnet. Fund the account with Friendbot, then mint test tokens.

    Mainnet uses real money. Keep amounts tiny, use a fresh wallet, and never commit a secret key. Build on testnet first, then flip the switch above.

TypeScript SDK

@soroswap/sdk is a typed client for the API. It never signs: build methods return unsigned XDR, you sign, then call send(). It is built for servers (Node 22+), so your API key stays out of the browser.

For a dApp, keep the SDK in a small backend (Next.js route, Express, Hono). The browser gets the XDR, the user signs in their wallet, and the backend submits.

REST API

Plain HTTPS and JSON, from any language. Add ?network= to each call. Amounts are strings in the token's smallest unit (7 decimals: 10000000 = 1 XLM). Full reference: ReDoc or Swagger.

Use this when a contract has to swap with nobody signing off-chain: a vault that rebalances, a DCA or savings contract, a game treasury paying out in USDC. Your Soroban contract calls the router directly, the same router the API uses for Soroswap pools. Source: soroswap/core.

Swap tokens your contract holds

The router calls to.require_auth() and pulls the input from to. When to is a user instead of your contract, the user signs the transaction and you skip authorize_as_current_contract. Simulate first with router_get_amounts_out to pick a safe amount_out_min.

Why the pre-authorization

When your contract calls the router, the router's to.require_auth() passes on its own: your contract is the direct caller. The router then calls the token's transfer on your contract's funds, one level deeper, and that check only passes if your contract authorized that exact call beforehand. Without it, simulation fails with Error(Auth, InvalidAction).

env.mock_all_auths() in unit tests hides a missing pre-auth, so deploy to testnet and run the swap once before your demo. Building on DeFindex too? A contract can swap here and deposit the output into a vault the same way: see hackathons.defindex.io.

Gotchas that eat hackathon hours

  • Amounts are integers with 7 decimals. 1 XLM = 10000000. The SDK wants bigint (10_000_000n); the API wants a string.
  • Two network enums. SupportedNetworks.TESTNET (Soroswap SDK) for SDK calls, Networks.TESTNET (Stellar SDK) when parsing XDR.
  • A bad or missing key returns 403, not 401. Check the Bearer prefix.
  • SDK errors are not Errors. On an HTTP error the SDK rejects with the API's response body, so log the whole object, not e.message.
  • Your key in the browser is public. Fine for a weekend demo, but proxy calls through a backend for anything real.
  • Trustlines. To receive a classic Stellar asset (like USDC), the receiving G... account needs a trustline first.
  • Liquidity must match the pool ratio. Read the pool with getPoolByTokens first, or simulation fails.
  • Don't hardcode testnet addresses. Testnet resets. Ask GET /api/testnet/router.
  • Error(Auth, InvalidAction) from your contract. The router pulls tokens from your contract one call deeper. Pre-authorize that transfer with authorize_as_current_contract, same amount and same pair.
  • Platform fees. On mainnet, set feeBps on the quote and referralId (your wallet) on the build to earn a cut of every swap your app routes.
